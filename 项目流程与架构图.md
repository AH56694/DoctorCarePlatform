# DoctorCarePlatform 工作流程与架构图

本文档根据当前代码整理，覆盖 `frontend`、`backend`、`python-service` 与基础设施之间的协作方式。可编辑版本同步维护在 [系统架构.drawio](系统架构.drawio)。

## 1. 系统总体架构

```mermaid
flowchart LR
    User["用户 / 管理员"] --> Browser["浏览器"]
    Browser --> Frontend["frontend\nReact + Vite"]
    Browser --> Nginx["Nginx\n统一入口 :8080"]

    Nginx --> Frontend
    Nginx -->|/api/*| Backend["backend\nFastAPI 业务服务 :8000"]
    Frontend -->|开发环境 /api/v1/*| Backend

    Backend -->|SQLAlchemy / PyMySQL| MySQL[("MySQL\n doctor_care_platform")]
    Backend -->|RAG_SERVICE_URL| PythonService["python-service\nAI/RAG 服务 :8300"]
    Backend -->|短信通知记录/发送| Sms["Aliyun SMS"]
    Backend -->|缓存/会话预留| Redis[("Redis")]
    Backend -->|文件对象预留| MinIO[("MinIO")]

    PythonService -->|兼容知识表/Agent 日志| MySQL
    PythonService -->|会话记忆| Redis
    PythonService -->|向量检索| VectorStore[("FAISS 本地索引\n或 Milvus")]
    PythonService -->|Embedding / LLM| Model["Ollama\nOpenAI-compatible\nDashScope/Qwen\n检索兜底"]
```

### 说明

- 前端在 Docker 场景可通过 Nginx 统一入口访问；本地开发时 Vite 默认运行在 `5173`。
- Nginx 当前将 `/api/` 转发到 `backend`，后端再作为 AI 网关访问 `python-service`。
- MySQL 是单一共享数据库，既保存业务表，也保存 Python AI 服务的兼容知识表和运行日志表。
- Redis、MinIO 已纳入 compose 和配置，其中 Redis 被 Python 服务用于会话记忆，MinIO 主要作为附件对象能力预留。

## 5. 智能问诊流式调用链

```mermaid
sequenceDiagram
    participant U as 用户
    participant F as 前端 Consultation
    participant B as backend /api/v1/ai/chat/stream
    participant R as RagServiceClient
    participant P as python-service /api/agent/run/stream
    participant A as RouterAgent / Agent 工作流
    participant T as ToolRegistry
    participant V as FAISS/Milvus + MySQL
    participant L as LLM/检索兜底
    participant DB as MySQL 业务表

    U->>F: 输入问诊内容，可附带会话上下文
    F->>B: POST /api/v1/ai/chat/stream
    B->>R: 转换为 Agent payload
    R->>P: POST /api/agent/run/stream
    P->>A: 路由到 chitchat / knowledge_qa / reasoning / admin / inspection
    A-->>B: SSE routed / step_started
    A->>T: memory_read / question_rewrite / knowledge_search / rerank
    T->>V: 检索知识片段和历史记忆
    V-->>T: 返回候选片段与元数据
    T-->>A: 返回工具结果与引用来源
    A->>L: 生成答案或使用检索兜底
    L-->>A: 答案文本
    A-->>B: SSE token / sources / end
    B->>R: 查询 run 状态和 tool_calls
    B->>DB: 写入 ai_sessions / ai_messages
    B-->>F: 继续转发 SSE
    F-->>U: 展示答案、引用、步骤和工具轨迹
```

## 6. Python Agent 内部流程

```mermaid
flowchart TD
    Input["用户输入"] --> Route["RouterAgent.route / route_stream"]
    Route --> Intent["IntentClassifier\nLLM 优先，关键词兜底"]
    Intent --> Task{"任务类型"}

    Task -->|chitchat| ChitChat["ChitchatAgent\n闲聊回答"]
    Task -->|identity_query| Identity["身份回答"]
    Task -->|knowledge_qa| KnowledgeQA["KnowledgeQAAgent\n知识问答"]
    Task -->|reasoning| Reasoning["ReasoningAgent\n问题分解 + 综合推理"]
    Task -->|admin_copilot| Admin["AdminCopilotAgent\n运营/后台助手"]
    Task -->|knowledge_inspection| Inspection["InspectionAgent\n知识巡检"]

    KnowledgeQA --> MemoryRead["读取会话记忆"]
    MemoryRead --> Rewrite["问题改写"]
    Rewrite --> Search["知识检索"]
    Search --> Rerank["重排/结果评估"]
    Rerank --> Generate["答案生成"]
    Generate --> MemoryWrite["写入会话记忆"]

    Reasoning --> Decompose["拆解子问题"]
    Decompose --> Search
    Admin --> Ops["OpsAgent / MySQL 统计"]
    Inspection --> InspectDB["检查知识质量、重复、陈旧、未命中"]
```

## 7. 管理员知识库维护流程

```mermaid
flowchart TD
    Admin["管理员"] --> KnowledgePage["前端 Knowledge 页面"]
    KnowledgePage --> ChooseCollection["选择知识分类\n症状问诊/用药咨询/报告解读/护理方法/招聘流程"]
    ChooseCollection --> Upload{"上传方式"}
    Upload -->|手动文本| TextContent["填写标题和内容"]
    Upload -->|文件上传| FileContent["读取文件 Base64\n文本文件同步提取内容"]

    TextContent --> BackendCreate["POST /api/v1/admin/knowledge-items"]
    FileContent --> BackendCreate
    BackendCreate --> SaveBusiness["backend 保存 ai_knowledge_chunks"]
    SaveBusiness --> Ingest["调用 python-service\nPOST /api/v1/knowledge/ingest"]
    Ingest --> Split["DocumentParser / TextSplitter\n解析和切片"]
    Split --> VectorWrite["写入 FAISS/Milvus"]
    VectorWrite --> MysqlChunks["写入 knowledge_doc / knowledge_chunk"]
    MysqlChunks --> ReturnCount["返回 chunks_count"]
    ReturnCount --> MarkIndexed["backend 更新 rag_status / rag_chunk_count"]

    KnowledgePage --> Delete["删除知识"]
    Delete --> BackendDelete["DELETE /api/v1/admin/knowledge-items/{id}"]
    BackendDelete --> RagDelete["DELETE /api/v1/knowledge/{doc_id}"]
    RagDelete --> RemoveVector["删除向量片段和兼容表数据"]
    BackendDelete --> RemoveBusiness["删除 ai_knowledge_chunks 记录"]
```

## 11. 阅读建议

1. 先看“系统总体架构”，明确三类应用服务和基础设施的边界。
2. 再看“用户身份与主业务流程”，理解患者、护理人员、管理员三类角色。
3. 接着看“护理招聘与匹配闭环”，这是平台业务主线。
4. 然后看“智能问诊流式调用链”和“Python Agent 内部流程”，理解 AI 问诊的网关、编排、工具和持久化。
5. 最后看数据关系和 API 模块地图，回到代码时更容易定位文件。
